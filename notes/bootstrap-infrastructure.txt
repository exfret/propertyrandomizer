Bootstrap infrastructure in complex contexts (2026-09-26)

The rule: a finite amount of bootstrap infrastructure that can then create an infinite amount of real infrastructure is allowed.
For example, bringing a mining drill to a planet to build more drills there, and eventually the automatable iron loop on Gleba.

What logic does now
 * Automatability already bootstraps: operating an entity of ours is automatic however it was built (entity-own-operable --> entity-operate, lib/logic/concrete.lua).
 * Isolatability bootstraps through the character, who is always local and can hand-craft from local materials.
 * On space surfaces, operating a building counts as local even when it was delivered (entity-own-space).
   This used to be on the building's presence (entity-build-architecture-space).
   That leaked: mining a delivered foundry back gave a "local" foundry item, and recycling it gave "local" tungsten carbide.
   Vanilla had 276 such fake platform contexts: foundries, processing units, superconductors, nutrients-fuelled organic crafting, and more.
 * Plants harvested by agricultural towers are automatable, like resources mined by drills (entity-harvest). That alone makes Gleba's iron loop isolatable and automatable.
   Off for now (AUTOMATABLE_PLANT_HARVESTING in lib/logic/concrete.lua, 2026-09-27): the new Gleba | 11 hard pebbles are lost in every monotone matching round with "added 0 needs", so first pass moved nothing. Turn it back on once refinement handles it.

The general rule, not implemented
Let a building's operation in a planet R count as local when R can then make the building itself.
That's a greatest fixpoint over (building, room) pairs:
  1. Start with every building allowed in every room.
  2. Sort with each allowed pair's operation counted as local, like entity-own-space.
  3. Drop the pairs whose building item isn't isolatable in R in that sort.
  4. Repeat until nothing drops.
It has to count the operation, not the presence, or mining back justifies every pair.
An earlier probe did it on presence, and Aquilo kept 107 buildings it can't make.

Measured on vanilla Space Age (seed 1, scratch probe in data-final-fixes.lua after the vanilla complex sort, plant harvesting on):
 * The fixpoint converges in 2 iterations, each a full complex sort with home contexts.
 * It adds 0 contexts on planets. The character can hand-craft its way out of every vanilla cycle, so any building a planet can make is already local there.
   Aquilo keeps no buildings; Gleba keeps 94, Vulcanus and Fulgora 89, Nauvis 84.
 * Counting every imported building as local everywhere, with no fixpoint, would add 1249 planet contexts instead.
   For example, imported foundries would count as local on Nauvis, which the rule above excludes.

So it's left out: it would cost about 3 extra sorts per logic build and change nothing in vanilla.
It would matter when randomization creates a cycle only machines can break, like a building whose recipe needs something only that building makes, in a category the character can't craft.
If that shows up, add it in logic.build.
The set it finds goes stale as randomization changes recipes, but the final check rebuilds logic and recomputes it.

Added for planetary freezing moves (2026-09-26, session f4, at a8's request)
 * Case: freezing moved to Vulcanus or Gleba. The heating tower needs concrete (recipe.lua:2369-2378), concrete needs an assembler (fluid ingredient), and assemblers freeze (heating_energy 100kW, space-age/base-data-updates.lua). So only a delivered first tower breaks the cycle.
 * Implemented: lib/logic/bootstrap.lua, run from logic.build after graph_setup, on candidates built in concrete.lua (entity-own-bootstrap = entity-build with [1]=true AND entity-own-bootstrap-rooms, a third option of entity-own-operable).
 * Scope: heat producers (categories.heat_producers) in the rooms lutils.bootstrap_heat_rooms names, which randomizations/planetary/freezing.lua sets to the planets a move made freeze. Vanilla Aquilo gets no candidates, so vanilla and every load without a freezing move pay nothing.
 * Cost: 1 extra sort per logic build while a freezing move is in the game (seeds 1-3: it kept the heating tower and nuclear reactor on Vulcanus and Gleba in 1 iteration; Fulgora keeps none, since it can't make towers).
 * Also changed: freezing is now heating_energy > 0 (EntityPrototype::heating_energy), no longer "not burner/heat powered". Characters and electric poles no longer freeze.
 * Warmth bootstraps too (user, 2026-09-26: "a handfed start as long as eventually no handfeeding is necessary is fine"). Drills, belts and inserters freeze, so automated fuel needs heat and automated heat needs automated fuel, which the logic's least fixpoint can't start.
   - Candidate edges room --> warmth (bootstrap_warmth, lib/logic/abstract.lua) for the same rooms.
   - A room keeps its edge only if heat is isolatable there in a sort without any warmth grant (a start by hand), and heat is isolatable and automatable there with the remaining grants (it keeps itself going).
   - Changed 2026-09-30: the candidate edge comes from a warmth-bootstrap AND node per room (the room, and heat through an edge that adds automatability) instead of the room itself. The grant then needs an isolatable context of heat in the room, which heat only has before the grant if it can be started without it, so the graph says that by itself and the separate warmth-free sort is gone. Pruning checks only that heat keeps itself going.
 * Randomization keeps the grants (2026-09-30). Unified's model counts a kept grant as fixed, but the next build prunes again, so a change that broke a justification lost the grant in the built game: on frozen Gleba 6 of 9 unified attempts failed UNIFIEDCHECK this way (the fix pass's copies had made heat startable there). bootstrap.justifications names what each kept grant needs (heat isolatable and automatable in the warmed room; a bootstrapped building's item isolatable in its room), and protection.planet_locked_recipe_contexts keeps those contexts like a locked recipe's.
 * Result (seeds 1-3, freezing only): freezing moved to Vulcanus and Gleba passes PLANETCHECK with 0 failures. Fulgora is rejected, since heat can't be started there. Cost: 2-3 sorts per logic build while a freezing move is in the game.
